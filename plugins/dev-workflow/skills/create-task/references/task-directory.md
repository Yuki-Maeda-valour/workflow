# タスクディレクトリ解決

タスク成果物を扱う skill は、保存・自動選択より前にこの契約で保存先を解決する。基準は **管理プロジェクトルート**（選択したプロジェクトのルート。profile がある場合は `.claude/` の親）である。profile の `root` は本体ソースの探索・実装・品質コマンド用で、保存先の基準にはしない。

## 優先順位

1. do-task / update-doc に明示されたタスク MD と、create-task の採用の経路に渡した `候補_` のパス(`/create-task <候補_ のパス>`)は最優先する。管理プロジェクトルート相対として解決し、profile や候補検出を行わない。完了時・採用時(`候補_` → `進行中_`)も同じディレクトリ内で状態名だけを変更する
2. profile の `task_dir` が文字列なら使用する。キー欠落または null は未指定。文字列以外、空文字、絶対パス、プロジェクト外、既存ファイルを指す値、`{{` と `}}` で囲まれた部分を含む値(init-project のテンプレートの置換漏れ。一重の `{x}` は対象外)はエラーとして停止する。置換漏れを未指定へフォールバックしない(保存先が変わったまま書き込みが進むのを防ぐ)。**例外として init-project だけは**、profile を生成・補完する側なので、置換漏れを未指定として検出へ進み、解決した値を補完案として提示する
3. 未指定時は管理ルート直下、`docs/` 直下、`.claude/` 直下の各ディレクトリを調べる。直下に通常ファイルの `進行中_*.md` / `完了_*.md` / `中断_*.md` / `保留_*.md` / `候補_*.md` があるディレクトリだけを候補にする(`候補_` だけのディレクトリも候補になる)。`_` 後が空の名前、空ディレクトリ、`.gitkeep` だけのディレクトリ、深い階層、シンボリックリンクは候補にしない
4. 候補に `{{` と `}}` で囲まれた部分を含む名前があれば(置換漏れのまま保存先として作られたディレクトリ)、中身を正しい保存先へ移してから消すよう求めてエラーとして停止する。それ以外は、候補が 1 件なら採用、0 件なら `docs/tasks`、複数なら候補を列挙して `task_dir` の明示を求め、作成・選択・移動を停止する

状態名と `task/{タスク名}` 形式のブランチ名はこの保存先から独立した規約である。既存タスクを別ディレクトリへ自動移動しない。

`候補_` は発見ループが書く、設計書の手前の候補である。書式は [task-template.md](task-template.md) の記法の規約、書き出しは [candidate-mode.md](candidate-mode.md) が正本。候補モードは必ずこの helper で解いた保存先に書く(新しい保存先を作るのは、状態名の MD が 1 つも無く既定の `docs/tasks` になるときだけ)。

## helper の使用

profile をホスト側で読み、`task_dir` の型を検証してから、同梱の [`../scripts/resolve-task-dir.py`](../scripts/resolve-task-dir.py) を実行する。YAML は helper に渡さない。

```bash
python3 <create-task-skill>/scripts/resolve-task-dir.py --project-root <管理ルート>
python3 <create-task-skill>/scripts/resolve-task-dir.py --project-root <管理ルート> --task-dir=<profileの文字列>
```

`--task-dir=<値>` の形なら、先頭が `-` の合法な相対パスもオプションと誤認されない。すべてのパスを引用する。JSON はデータとして解析し、シェル評価しない。

- exit 0: `task_dir`（管理ルート相対）、`path`（絶対）、`source`（`profile` / `detected` / `default`）
- exit 1: `error`。無効指定(置換漏れを含む。その名前のパスが既に在れば、中身を移してから消す案内を添える)、置換漏れの名前の候補、管理ルート・候補の読取り不能
- exit 2: `error` とソート済み `candidates`。候補が複数

helper は読取り専用で、ディレクトリ作成・タスク本文の読取り・移動を行わない。指定ディレクトリが内部のシンボリックリンクなら実体が管理プロジェクト内にある場合だけ使え、返す `task_dir` と `path` はその実体へ正規化する。外部を指す場合はエラーにする。既定パスも同じ検証を通す。

Python が無い環境では、上の優先順位・探索深度・通常ファイルとシンボリックリンクの条件を同じまま読み取り専用で実施する。候補の複数検出や無効指定を既定値へフォールバックさせない。
