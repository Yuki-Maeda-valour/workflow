# 権威参照ファイルの判定(import の判定・ドリフト判定)

`AGENTS.md` と `CLAUDE.md` 系(`CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md`)の関係を扱う skill(init-project / understand-project / update-doc)は、この 1 本を兄弟参照して判定する(同じ判定を複写しない)。

Claude Code は Codex / Cursor と違い、既定設定では `AGENTS.md` を無条件には読まない — `CLAUDE.md` 系があると直読みが止まる。ここではこの最小限の前提だけを踏まえ、判定手順だけを書く(公式の挙動の詳細は design 側にあり、ここには複写しない)。

## (0) 基点

権威参照ファイルを検出するのと同じルート(**管理プロジェクトルート**。profile の `root` ではない)を基点にする。対象はそのルートの `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` の 3 種。上位階層・parent-child 構成の本体側・モノレポのサブディレクトリは見ない。

## (1) import の判定(1 ファイルについて)

互換形かどうかの判定に使うのはこれだけ(下の「使い分け」参照)。

1. **symlink**: そのファイルが、ルートの `AGENTS.md` への symlink なら「import あり」と同じに扱う。**symlink かどうかは、ファイルの種類(リンクか)と解決先(ルートの `AGENTS.md` と一致するか)で判定し、中身を読んで判断しない**(Read や Grep はリンクの解決先の内容を返すため、中身だけを見ると「`@` 表記が無い = import なし」と誤判定する)。
2. **import 記法**: **ルートの `AGENTS.md` への symlink でなければ**(他のファイルへの symlink は、リンクの解決先の内容を、**リンク自身の位置**〈ホストが読むパス〉から解決して判定する)、コードブロック(3 連バッククォート)内・インラインコード(バッククォート)内を除いた `@パス` を、**import を書いたファイルの位置から解決**し、ルートの `AGENTS.md` に一致すれば「import あり」。`CLAUDE.md`・`CLAUDE.local.md` の `@AGENTS.md`、`.claude/CLAUDE.md` の `@../AGENTS.md` は**例**であり、文字列の一致で判定しない(`@./AGENTS.md` や絶対パスも一致しうる)。**`.claude/CLAUDE.md` の相対パスの基準は公式の記述からの導出であり、実測はしていない**。
3. どちらでもなければ「import なし」。
4. **間接 import は追わない**(import 先のファイルの中にある import までは辿らない。既知の限界)。

## (2) ドリフト判定(ルートの 3 種について)

注記専用。`AGENTS.md` があり、(0) の 3 種が 1 つ以上あるのに、**そのいずれも** (1) で「import なし」のときだけドリフト。1 つでも「import あり」(symlink を含む)なら正常で、警告しない。ただし (3)② の構成(`AGENTS.md` 自体が 3 種のいずれかへの symlink)はドリフトとしない。

ドリフトのときは「この環境では `AGENTS.md` が読まれない」と注記し、対処を 2 つ案内する: ルートの `AGENTS.md` を指す import の追加、またはユーザー設定 **`claude-md-and-agents-md`** への変更(プロジェクト設定・ローカル設定に書いても効かない)。**`CLAUDE.local.md` は個人のファイルなので、この判定結果は実行した環境についてのもの**であり、他の環境では異なりうる。

## (3) 対処を提案・案内するときの共通規則

(1) にもとづく init-project の提案からも、(2) にもとづく注記からも、この規則を参照する。

1. **symlink には import を書き足さない**。
2. **`AGENTS.md` 自体が (0) の 3 種のいずれかへの symlink のときは、ドリフトとしない**。「`AGENTS.md` は <解決先> へのリンクで、内容はそのファイル経由で読まれている」と構成を報告するだけにし、import の追加もユーザー設定の変更も提案・案内しない(リンク先に import を書き足すと `AGENTS.md` の実体に自己 import が入る)。解決先が (0) の 3 種以外(例: `docs/AGENTS.md`)なら、通常どおり判定・案内する。

## 使い分け

- **init-project の互換形の判定**(ルートの `CLAUDE.md` 自身に当てる)には**(1) だけ**を使う。**(2) は注記専用であり互換形の判定には使わない**。
- **(3) はどちらの経路からも参照する**共通規則。

## 既知の限界

- 間接 import(import 先のファイルの中にある import)は追わない。`CLAUDE.md` が別ファイル経由で `AGENTS.md` を読む構成は「import なし」と判定されうる。
- `.claude/CLAUDE.md` の相対パス(`@../AGENTS.md`)は公式の記述からの導出であり、実測していない。
- **他のファイルへの symlink をリンク自身の位置から解決して判定する基準も、公式の記述からの導出であり、実測していない**。
- **上位階層の `CLAUDE.md` 系も直読みを止めるが、この判定は見ない((0))。上位にある構成では (2) が『正常』でも読まれていないことがある**。
- `.claude/rules/` はこの判定の対象外(読まない)。ホストが自動で読む指示ファイルであり、skill の読取り・同期の対象外(design §3・§7-4)。
