# MCP 設定生成(`.mcp.json` / `.codex/config.toml`)の詳細手順

`SKILL.md` Phase 3-7(MCP サーバー設定の生成)から参照する。ここには**判定の詳細手順**だけを置き、方針(なぜそうするか)は `docs/design.md` §7-6 が正本のため再掲しない。

## 1. `.codex/config.toml` の既存 id 判定(append-only の前提)

**目的**: 追記前に「どの id が既に宣言済みか」を安全側に判定する。誤って既存 id を見落として二重追記すると `Cannot declare ... twice` で TOML が壊れるため、**判定を誤るなら「退避して報告する」側に倒す**。

**本節での「退避」の定義**: **追記せず生成を見送り、理由を報告すること**を指す(既存ファイルを移動・改名・改変することではない。既存行・コメント・キー順序には一切触れない)。

**共通前提(パーサ経路以外のすべてのテキスト検査に経路非依存で適用する。節を限定して列挙しない — 新設する節にも自動的に係る)**:

1. **判定はコメント(`#` 以降の残り)と複数行文字列(`"""…"""` / `'''…'''`)を除いた範囲に対して行う**。**ただし基本文字列 `"…"` / リテラル文字列 `'…'` の内部にある `#` はコメント開始ではない**(TOML の仕様どおり。実測: `command = "a#b"` は `#` 以降を切り詰めずに `a#b` という値のままパースされる。素朴に「最初の `#` 以降を捨てる」実装だと `"a` のように値が途中で切れ、再パースが `TOMLDecodeError` になる)。**守らない実装は必須の退避を見落としてファイルを壊す**(1-1 のパーサ経路はコメント・文字列を構造的に無視するためこれを自動的に満たす。反例は 1-4)。**この但し書きの影響範囲は 1-3 の値比較だけ**で、切り詰めによる誤りは偽の不一致(据え置き + 報告)という安全側にしか倒れない(見出し・トップレベルキーは行頭に単独で現れるため、この切り詰めで見落とすことはない)。
2. **テーブル見出し・キーは、行頭(空白のみが前置される位置)に現れるものだけを見出し / キーとみなす**。**守らない実装も同様にファイルを壊す**(文字列リテラルの内部に現れる `[...]` や `key =` に似た文字列を見出し・キーとして扱うと、例えば `notify = "see [profiles.work]"` の `[profiles.work]` を見出しと誤認する。反例は 1-4)。
3. **見出し・キーの解析は TOML の空白許容規則に従う** — **共通前提 2 の「行頭(空白のみが前置される位置。タブも許容)」の許容に加えて**、角括弧の内側・ドットの前後・キーと `=` の前後の空白も無視して**正規化してから判定する**(`  [ mcp_servers . serena ]` は `[mcp_servers.serena]` と同一に扱う。1 セグメントの判定にも同様に効く — `  mcp_servers = { … }` のような前置空白付きのキーも不変条件②の対象として認識する)。**守らない実装は既存 id を見落として二重宣言を起こし、ファイルを壊す**(実測: `[ mcp_servers.serena ]` / `[mcp_servers . serena]` はいずれも `[mcp_servers.serena]` とパース結果が完全一致するが、空白を許容しない素朴な抽出では抽出規則のどのカテゴリにも一致せず、id が見つからない「空虚な真」を誘発する。反例は 1-2)。
4. **判定単位は `mcp_servers` 直下の各サーバー id(1 段目のセグメント)であり、その id 配下の 2 段目以降(サブテーブル見出し `[mcp_servers.<id>.<name>]`・インラインの子テーブル `env = {...}`・その他のキー `startup_timeout_sec` 等)は id 自身の宣言記法の判定に含めない**。**これは不要な退避を減らすための限定であり、守らないと再実行モードが機能退行する**(壊れはしない。実測: これらが付随していても新しい id の追記は合法。反例は 1-2)。`[mcp_servers.<id>.<name>]` のような 3 段以上の見出しは、`<id>` を別の/新しい id とは扱わず、既に見出し形で宣言済みの `<id>` の一部として扱う。

### 1-1. パーサを検出できた場合(推奨経路)

`tomllib`(Python 3.11+ 標準)または `tomli` が実行時に使えるか確認する。使えれば対象ファイルをパースする。

- **まずトップレベルに `mcp_servers` キーが存在するかどうかを確認し、次の 3 分岐で扱う**(存在しない場合と、存在して型が違う場合を混同しない):
  1. **キーが存在しない** → **既存 id なし**として扱う。id 集合を空とし、宣言された id をすべて追記してよい(実測: 追記は合法で、追記した id は `mcp_servers` 直下の dict のキーとして正しく可視になる。「既に `config.toml` を持つが `mcp_servers` はまだ無い」は宣言駆動として最も普通の入力であり、ここを退避に倒すと主経路で最も普通の入力が生成されなくなる)。
  2. **キーが存在するが dict でない**(文字列・数値・配列、および配列テーブル `[[mcp_servers]]` に由来するリスト等)→ **id を 1 つも取得せず 1-4 の不変条件②により全体退避する**。
  3. **キーが存在して dict** → 以下のとおり id 集合を取得する。
- (上記 3 で)dict であれば、`mcp_servers` 直下の id 集合を**正確に**取得する(grep の見落としが消える)。
- **ただし「追記可能かどうか」はこの id 集合の取得だけでは判別できない**。`[mcp_servers.<id>]` 見出し形とインラインテーブル形(`mcp_servers = { <id> = {...} }`)はどちらも `mcp_servers` の値が dict になり、パース結果が完全一致するため、パース経路でも下記 1-4 の**トップレベルのインラインテーブル検査はテキストで別途行う**。
- id 集合の取得だけで済むのは「既存 id 集合の取得」までで、他記法(`[mcp_servers]` + インラインテーブル・ドットキー・引用キー見出し)が混在していても**新規 id の追記は合法**なので、パーサが使える環境ではこの混在を退避理由にしない(下記 1-5 の経路条件)。

### 1-2. パーサを検出できない場合(縮退・基準線)

`tomli` / `tomllib` がいずれも無い環境では、次の**テキスト判定**に縮退する(共通前提の 1〜4 を満たしたうえで判定する。`.codex/config.toml` は MCP 専用ファイルではなく `model` / `approval_policy` 等の無関係なキー・セクションが同居しうる。design §7-3)。

**候補行(宣言の可能性がある行)を次の 4 種に限定して扱う。これに該当しない `mcp_servers` という文字列の出現は候補行に含めない**(右辺の値〈文字列・配列等〉に現れる `mcp_servers` / キーパスの先頭セグメントが `mcp_servers` でないトップレベルの多段ドットキー〈`profiles.work.mcp_servers = {...}` 等。1-4 が対象外と規定するものと同じ〉は候補行ではない):

1. **直前にテーブル見出しが無い(トップレベル)状態で、キーの左辺 1 段目が `mcp_servers` であるキー行**(`mcp_servers = …`〈1 セグメント〉/ `mcp_servers.<id> = …` / `mcp_servers.<id>.<field> = …`〈2 段以上のドットキー〉)
2. **キーパスの 1 段目が `mcp_servers` であるテーブル見出し行**(`[mcp_servers]` / `[mcp_servers.<id>]`〈`<id>` は bare key・引用キー〈二重引用 `"..."`・単一引用 `'...'` のいずれも〉を問わない〉/ `[mcp_servers.<id>.<name>]` / `[[mcp_servers]]`)
3. **表テーブル見出し `[mcp_servers]`(配列テーブル `[[mcp_servers]]` は含まない — `[[mcp_servers]]` 自体は候補 2 で検出され【退避優先 2】の対象になるため、その配下の行は id 判定に用いない)の配下(次の見出しまで)に現れるキー行**(左辺の**先頭セグメントを id として読む** — この読み替えは候補 3 だけの解釈であり、候補 1・4 の「左辺 1 段目が `mcp_servers` である」という**抽出条件はここには掛からない**。例: `[mcp_servers]` 配下の `serena = { command = "uvx" }` は左辺 1 段目が `serena` であり `mcp_servers` ではないが、候補 3 としてこの行を id `serena` の宣言と読む)
4. **トップレベル以外(`[mcp_servers]` 以外のテーブル見出しの配下)に現れる、キーの左辺 1 段目が `mcp_servers` であるキー行**(候補 1 と同じ広さ — `mcp_servers = …` / `mcp_servers.<id> = …` / `mcp_servers.<id>.<field> = …` のいずれも。例: `[profiles.work]` 配下の `mcp_servers = { a = 1 }` や `mcp_servers.serena = { … }`。実効パスは `<table>.mcp_servers`(またはその配下)という別物で、**id を宣言せず、1-4 の不変条件②の対象でもない**)

候補行から**各サーバー id がどの記法で宣言されているかを判定する。⚠ 以下は優先順位付きの分岐であり、上から順に best-effort で見るのではなく、【退避優先 1〜3】が 1 つでも成立すればそれを優先する。【追記可】は【退避優先 1〜3】がすべて不成立のときに限って成立する**(**候補 4 の分類は判定の前処理であり、この優先順位の対象ではない** — id 集合の数え上げに使う情報を確定させるだけで、退避 / 追記のどちらとも競合しない):

- **候補 4 に該当する行は「分類済み・id 宣言なし」として扱う**(別物なので id 集合にもカウントしないが、退避の引き金にもしない)。
- **【退避優先 1】次のいずれかの行が 1 行でもある**(候補 3〈`[mcp_servers]` 配下のキー行〉/ 候補 1 のうち 2 段以上のドットキー `mcp_servers.<id>.command = ...` / 候補 2 のうち引用キー見出し `[mcp_servers."<id>"]` ・ `[mcp_servers.'<id>']`〈二重引用・単一引用のいずれも〉)→ **`mcp_servers` 部分だけを全体退避**し、同名判定を試みず生成せず報告する(grep では新規 id の追記が安全かどうかを判定できないため。**他記法が TOML として不正だからではない** — 新規 id の追記自体は合法。壊れるのは同名 id の二重宣言だけであり、それを見落とすリスクを避けるための安全側の退避)。**この分岐は「行の存在」で判定する — その行が宣言する id を下記の id 集合の定義で数えられるかどうかは問わない**(下記の id 集合の定義は【追記可】と 1-3 の内容比較のためのものであり、この分岐の発火条件には掛からない)。
- **【退避優先 2】候補 1 のうち 1 セグメント(`mcp_servers = …`)、または候補 2 のうち `[[mcp_servers]]`(配列テーブル)が 1 つでもある** → id を宣言しないので id 集合には数えないが、**1-4 の不変条件②の対象として全体退避する**(理由は 1-4)。**この分岐は他の候補 2 見出し(`[mcp_servers.<id>]` 等)が同居していても発火する** — `[[mcp_servers]]` は既存 id を配列要素の内部に紛れさせるため、他の見出しがすべて bare key の見出し形であっても優先して退避する。
- **【退避優先 3】⚠ 共通前提 1・2・3 を適用したうえで、見出し(`[…]` / `[[…]]`)のキーパスの**1 段目**が `mcp_servers` である行、またはキー行の左辺のキーパスの**1 段目**が `mcp_servers` である行が 1 行以上あるのに、上記(候補 1〜4)のどの分類にも当てはまらない場合は、記法を判定できていないとみなして全体退避する**(**空虚な真の防止**。**候補の各定義と同じ「1 段目」基準で判定する**〈「含む」で判定すると `profiles.work.mcp_servers = { … }` のようなキーパスの**末尾**に `mcp_servers` が現れるだけの行まで拾ってしまい、候補行の定義で明示的に対象外とした行が退避側に引き戻される〉。**この判定は共通前提 1(コメント除外)を適用した後の内容に対して行う。コメント内にのみ現れる `mcp_servers` の言及はここでの判定に数えない**〈反例は下の「コメントだけがあるファイル」の段落〉。ガードは見出し・キー左辺の**1 段目**という位置だけを見る — 右辺の値〈文字列・配列〉に文字列として現れる `mcp_servers` は元々候補行ではないため、この判定にも現れない。候補行の定義自体が想定していない書き方を完全には排除できないための最後の安全網。「候補行はあるが分類できない」と「候補行が本当に無い」を区別できないため判定不能側に倒す)。
- **【追記可(退避優先 1〜3 がすべて不成立のときだけ)】見つかった id が 1 個以上あり、そのすべてが候補 2 のうち `[mcp_servers.<id>]`(`<id>` が **bare key** の)見出し形で宣言されている** → その id 集合を既存として扱い、無い id だけ末尾に追記する(内容比較は 1-3 を参照)。
- **id 集合には、候補 2 の `[mcp_servers.<id>]` 見出し(`<id>` が **bare key・2 段**なら**見出し形の宣言**、**引用キー〈二重引用・単一引用〉なら見出し形以外の宣言**として数える)、**候補 3 のキー行**(`[mcp_servers]` 配下)、候補 1 のうち 2 段以上のドットキーによって宣言された id を数える。**それ以外の候補(3 段以上の見出しを含む)はいずれも id 宣言に数えない**。**したがって「id を宣言する行が 1 行も無い場合」だけが「既存 id なし」で新規追記できる**(実測: `[mcp_servers]` 単独のファイルは `mcp_servers` の値が空 dict になり、新しい id の追記は成功する)。**⚠ この数え方は【追記可】と 1-3 の内容比較に使う id 集合の定義であり、【退避優先 1〜3】の発火条件には掛からない**(退避条件は id の個数ではなく候補行の存在で判定する — **数え方の定義を変えても退避の発火が影響を受けないようにするための分離**)。

**候補行の限定・候補 4 の新設が無いと退避が過剰発火する(実測)**: `notify = "run [mcp_servers.serena] first"` / `notify = ["notify-send", "mcp_servers updated"]` は**右辺の値**にしか `mcp_servers` が現れないため候補行にならず、ガードの対象にもならない。`[profiles.work]` 配下の `mcp_servers = { a = … }` は候補 4 として分類され「id 宣言なし」で処理が終わる。`profiles.work.mcp_servers = { a = … }` はキーパスの先頭セグメントが `profiles` であり最初から候補行ではない。いずれも `[mcp_servers.chrome-devtools]` の追記は成功し id も可視になるが、位置を見ずに「文字列を含む」だけを条件にすると誤って全体退避に倒れ、1-5 が禁じる「既存に無関係な宣言 1 件で新しい id が永久に追加できない」という機能退行を起こす。

**反例(コメントだけがあるファイル。§1-1 との対称性)**: `# mcp_servers = {}` / `# [mcp_servers.example]` のように**コメント行にしか `mcp_servers` が現れないファイル**。**共通前提 1(コメント除外)を適用した後の内容に対してガードを判定する**ため、この適用後は該当する行が無くなり、**「id を宣言する行が 1 行も無い」側に落ちて既存 id なしとして追記できる**(実測: `tomllib` でもこの構成は `mcp_servers` キー自体が存在せず〈`NoneType`〉、§1-1 の「キーが存在しない → 既存 id なし」と**同じ結論**になり、経路間の対称性が保たれる。Codex の雛形にコメントアウトされた `mcp_servers` の例が含まれる現実的な入力を不要にブロックしないため)。

**反例(空虚な真を塞がないと壊れる)**: `[mcp_servers]` の直後に `serena = { command = "uvx" }` があるだけの構成。子キー行を抜き出す規則が無いと `serena = {...}` の左辺は `mcp_servers` を含まないため抽出漏れし、`[mcp_servers]` 見出しだけが残って id 0 個の「全て見出し形(空虚に真)」と誤判定される。`[mcp_servers.chrome-devtools]` を追記すると `Cannot declare ('mcp_servers','chrome-devtools') twice` で壊れる。上記の「`[mcp_servers]` 配下のキー行も抜き出す」規則と「空虚な真の防止」の両方でこれを塞ぐ。

**反例(共通前提 4 を落とすと不要な退避に倒れる)**: `[mcp_servers.serena]` の直後に `[mcp_servers.serena.env]` や `startup_timeout_sec = 30` があるだけの構成。`env` サブテーブルや付随キーは id の宣言記法に無関係なので、これらを「他記法」と数えて退避すると、serena 以外の新しい id(例: chrome-devtools)を追加できるはずなのに永久に追加できなくなる(1-5 が禁じる自家中毒と同型)。

### 1-3. 既存 id の内容比較(不一致の検出)

id が既存として判定されたら(1-1 のパーサ経由でも、1-2 のテキスト判定経由でも)、**その id ごとに宣言内容(`command` / `args`)を解決後の宣言と比較する**。パーサがあれば構造的に比較する。テキスト判定の場合は(**共通前提 1・2・3 を適用した範囲で**)、該当 `[mcp_servers.<id>]` 見出しから**次の同格以上の見出し**(別の id・`mcp_servers` 以外のテーブル・`mcp_servers` に関する範囲の終わり)までの行を抜き出す(共通前提 4 のとおり、`[mcp_servers.<id>.<name>]` のようなその id 自身のサブテーブル見出しは範囲に含める)。抜き出した範囲から `command` / `args` の値を文字列比較する。

- **一致** → 何もしない(報告のみ)。
- **不一致** → **追記も置換もしない**(`.codex/config.toml` には書き込み手段が無いため、`.mcp.json` のような「新旧対比→承認→置換」は行わず、**据え置くだけ**にする)。**不一致の事実・据え置いたこと・貼り付け用スニペット(利用者が手で貼れる `[mcp_servers.<id>]` ブロック)を必ず報告する**(無言スキップ禁止。design §5-9。`.mcp.json` 側の「不一致を検出したら必ず報告する」と報告義務を揃える)。

**この比較を行わずに「既存 id は無条件で追記対象外」とだけ扱ってはいけない** — 承認して生成し直したはずの宣言が、内容の変わった既存セクションの陰に隠れて黙って古いまま残る事故になる。

**共通前提 1・2 を適用しない場合の危険側の反例**: `[mcp_servers.serena]` の配下に `command = "npx"` の実キーと `# command = "uvx"` というコメントが両方ある構成で、解決後の宣言が `uvx` のとき、コメント側を拾うと「一致 → 報告のみ」に誤判定し、**承認して生成し直したはずの宣言が黙って古い `npx` のまま残る**(design §5-9 の報告義務が無効化される)。共通前提 2(行頭のみ見出し/キー)を適用しない場合の反例(`notify = "see [mcp_servers.other]"` を次の見出しと誤認して範囲が早く切れる)は、範囲が狭くなるだけで結果は偽の不一致になり、据え置き + 報告という安全側にしか倒れない。

### 1-4. トップレベルの `mcp_servers` が見出し形以外で定義されている場合の検出(経路に依存せず必須・不変条件②)

`mcp_servers` が**トップレベル**で `[mcp_servers.<id>]` **見出し形以外の何か**として定義されていたら、パーサの有無に関わらず**必ず退避する**。対象は次のいずれか(**インラインテーブル・スカラー・配列は、キーパスが `mcp_servers` そのもの〈1 セグメント〉である場合に限る** — `mcp_servers.<id>` のような 2 段以上のドットキーは id 1 件の宣言にすぎず、他 id の追記を妨げないため対象**外**。1-2 の「見出し形以外」として扱う):

- **インラインテーブル**: `mcp_servers = { … }`
- **文字列・数値等のスカラー値**: `mcp_servers = "…"` / `mcp_servers = 123` 等
- **配列**: `mcp_servers = []`
- **配列テーブル**: `[[mcp_servers]]`

**理由は形によって異なる**: インラインテーブル・スカラー・配列は、新しい id の追記であっても `Cannot declare ...` / `Cannot overwrite a value` で**構造的に失敗する**(構造上必須の退避)。**配列テーブル `[[mcp_servers]]` は追記自体はパースに成功する**が、新しい id が `mcp_servers` 直下のテーブルではなく配列要素の内部(例 `mcp_servers[0]`)に紛れ込み、**Codex はそのサーバーを認識しない**(パースが通ることは正しく生成できたことの証明にならない。追加の確認は §3)。**だからこそ明示的な検出が必要になる**(自然にエラーにならない形があるため、検出漏れがあると「生成した」と報告しながら実体が無い事故につながる)。

判定は素朴な `mcp_servers\s*=\s*{` の grep では**足りない**。トップレベルの `mcp_servers` の検出は**キーパスが `mcp_servers` そのもの(1 セグメント。ドットなし)であるトップレベルのキー行(右辺の型を問わない)と `[[mcp_servers]]` 見出しの両方**を対象にする。**`mcp_servers.<id>` のような 2 段以上のドットキーはここでの検出対象に含めない**(id 1 件の宣言であり、新しい別 id の追記を妨げない。実測)。`[profiles.work]` のようなテーブル見出しの配下にある同名キー `mcp_servers = { … }` は `profiles.work.mcp_servers` という別物で、この場合は `[mcp_servers.<id>]` の追記が成功する。**直前のテーブル見出しを追跡し、`[...]` の配下に現れる `mcp_servers = ...` は対象外とする**。**あわせてキーパスが `mcp_servers` そのもの(1 セグメント)であることも確認する**(`profiles.work.mcp_servers = { … }` のようなトップレベルのドットキーは、直前にテーブル見出しが無くても `profiles.work.mcp_servers` という別物であり、`[mcp_servers.<id>]` の追記は成功する。同様に `mcp_servers.serena = { … }` も、キーパスが「`mcp_servers` で始まる」だけで「`mcp_servers` そのもの」ではないため対象外とする。**「で始まる」ではなく「そのもの(1 セグメント)」で判定しないと、`mcp_servers.<id>` 形の正当な他記法まで巻き込んで不要な退避に倒れる**)。

**見出し追跡・キーパス確認は共通前提の 1・2・3(コメント・複数行文字列の除外 + 行頭のみを見出しとみなす + 空白の正規化)を適用したうえで行う。** これにより次の 2 例が正しく「真のトップレベル」と判定される(適用しなければ誤って「対象外(退避しない)」と判定し、`[mcp_servers.chrome-devtools]` の追記が `Cannot declare ('mcp_servers','chrome-devtools') twice` で**ファイルを壊す**):

- `# [profiles.work]`(**コメント化された見出し**)+ 次行に `mcp_servers = { … }` — 共通前提 1(コメント除外)により、この行は見出しとして扱われない
- `notify = "see [profiles.work]"`(**文字列内の角括弧**)+ 次行に `mcp_servers = { … }` — 共通前提 2(行頭のみ見出し)により、この行は `notify` から始まるため見出しとして扱われない

**パーサなし経路では §3 のパース検証がスキップされる**ため、共通前提を適用しないまま追記すると上の 2 例は**壊れたまま復元されず残る**(design §7-3)。パーサがある経路では 1-1 のとおりこの誤判定自体が起きない。

### 1-5. 経路と退避の対応(不変条件は 2 つ)

| 経路 | (a) トップレベルの `mcp_servers`(1 セグメント)が見出し形以外(インラインテーブル・スカラー・配列)/ 配列テーブル `[[mcp_servers]]` | (b) `[mcp_servers]`+インラインテーブル / `mcp_servers.<id>` ドットキー(2 段以上)/ 引用キー見出し |
|---|---|---|
| パーサあり | 退避する(構造上必須。**スカラー・配列・配列テーブルは型確認で判別可能、インラインテーブルは 1-1 のとおりテキスト検査〈1-4〉が必要**〈dict 型はインラインテーブルと見出し形の両方で生じ、型確認だけでは区別できないため〉) | **退避しない**。パースした id 集合で無い id だけ追記できる |
| パーサなし(縮退) | 退避する(構造上必須) | 退避する(grep では同名判定ができないため) |

**両経路で守る不変条件は 2 つ**: ①**同名 id には絶対に追記しない**(id が 1 個も抽出できない場合を「同名 id なし」と誤認しない。1-2 の空虚な真の防止を含む)②**トップレベルの `mcp_servers`(キーパスが 1 セグメントであるもの)が `[mcp_servers.<id>]` 見出し形以外の何か(インラインテーブル・スカラー・配列)として定義されている場合、または `[[mcp_servers]]`(配列テーブル)として定義されている場合は追記しない**。**`mcp_servers.<id>` のような 2 段以上のドットキーはこの対象ではない**(id 1 件の宣言であり、他 id の追記を妨げない。(b) として扱う)。**「どの記法であれ現れたら退避」にしない** — 既存に無関係な他サーバーの宣言が 1 件あるだけで新しい id が永久に追加できなくなり、再実行(アップデート)モードが機能退行する。

## 2. 追記の実施

1. **改行終端の確認**: 追記前に末尾が改行で終わっているか確認し、終わっていなければ改行を 1 つ足す。追記ブロックの前に空行を 1 行入れる(終端を確認せずに追記すると、既存の最終行と連結して壊れる。前例の `.gitignore` 追記もこの確認を持たないため、同じ欠陥を写さない)。
2. **ファイルが無い場合**: `.codex/` ディレクトリの作成を含め新規作成する。
3. **無い id だけ**(1-1 / 1-2 で既存として判定されなかった id のみ。1-3 の比較結果が一致・不一致のいずれであっても、既存 id は追記対象外)、`[mcp_servers.<id>]` + `command` + `args` の形で書く。**値の表現とエスケープ規則(TOML 基本文字列で書く・エスケープ対象・`args` 省略時の扱い)は `SKILL.md` Phase 3-7 の「値のエスケープ」が正本**(同じ事実を 2 箇所に書かない)。

## 3. 生成後の検証とロールバック

**唯一の安全弁**: 追記後に再 Read して、次の 2 段階を確かめる(パーサが使える環境のみ)。

1. **パースが例外なく成功すること**
2. **追記した各 id が `mcp_servers` 直下のテーブル(dict)のキーとして現れること**(`mcp_servers` 自体が配列・配列テーブルの要素内に紛れていないか、スカラーに変わっていないかを含む)

**①だけでは不十分**: 配列テーブル `[[mcp_servers]]` はパースには成功するが、追記した id が配列要素の中に入ってしまい Codex から見えない(1-4 参照)。**②まで満たして初めて追記を確定する。**

- **①②とも成功**: 追記を確定する。
- **①または②のいずれかが失敗**: 追記を取り消す。**追記前に Read した内容をそのまま保持しておき、その内容で全体 Write して復元する**(「既存行・コメント・キー順序に一切触れない」規則の**唯一の例外**)。復元後の報告に、追記しなかったこと・失敗した段階(①パース失敗 / ②構造不正)・貼り付け用スニペット(`[mcp_servers.<id>]` ブロックを利用者が手で貼れる形)を含める。
- **パーサが無い環境**: この 2 段階の検証をスキップし、スキップした事実を報告する(検証できないことを黙らない)。

## 4. 恒久的な限界(報告に明記する)

1. **不一致の置換ができない**: `.mcp.json` は承認付きで置換できるが、`.codex/config.toml` は書き込み手段が無いため**報告 + 据え置き + 貼り付け用スニペット**まで。
2. **他記法が混在するファイルには追記できない**(全体退避。パーサを検出できた経路では 1-5 の表のとおり解消する)。
3. **「初回しか書けない」ではない**: 新しい id の追記は 2 回目以降も可能。封じてはいけない(1-5 の不変条件を参照)。
