# cleanup — 作業の残りの棚卸しと片付け

AI のセッションが作って残した worktree・作業用コンテナ・作業ファイルを集め、分類し、承認を得て消す。方針の正本(ほかが合わせる元)は design §5-26。

## 原則

- **集める段階は読み取りだけ。** 消す操作は、承認の後に、対象ごとに次のものだけを使う。
  - worktree: `git worktree remove <パス>`(`--force` なし)。ロック付きは 4 節の条件を満たしたときだけ、先に `git worktree unlock <パス>`
  - コンテナ: `<実行環境> rm <ID>`(`-f` なし。動いているものは消さない)
  - ボリューム: `<実行環境> volume rm <名前>`
  - 作業ファイル: 1 件ずつの削除
  - 記録だけ残った worktree: `git worktree prune`(リポジトリ全体の `prunable` をまとめて刈る。1 件ずつは選べない。4 節 8)
- **ローカルのブランチも、リモートのブランチも消さない。**
- **使用中のものは消さない。** 中を作業ディレクトリにしているプロセスがある worktree と、持ち主のプロセスが生きているロックは、残す。
- **ほかにコピーの無いものは個別に確認する。** 未コミットの変更・無視されたファイル(`.env`・ローカル DB・ビルド成果物)・DB のボリュームは、一括の承認に含めない。
  - `git worktree remove` は、`--force` が無くても、無視されたファイルを消す。
- プロジェクト固有のパス・コマンドは書かない。リポジトリの場所は `git rev-parse --show-toplevel` で調べる。
- **人が読む文(報告・質問・PR と Issue の本文・作る文書・コミットメッセージ)を書く前に [../do-task/references/writing-for-people.md](../do-task/references/writing-for-people.md) を読み、それに従う**
  - このファイルに届かないときは、権威参照ファイル(AI への指示をまとめたプロジェクトのファイル。`AGENTS.md`。無ければ `CLAUDE.md`)の「応答の書き方」節に従い、届かないことを報告に書く

## 1. worktree を集める

1. `git worktree list --porcelain` で一覧を取る。先頭の 1 件(本体)は対象外。`detached`・`locked`・`prunable` の行も読む。
2. 既定ブランチを `git symbolic-ref refs/remotes/origin/HEAD` で調べる。失敗したとき(未設定・origin が無い)は「未確認」とし、取り込みの判定は PR の状態だけで行うか、「確認が必要」に入れる。
3. 各 worktree の読み取り(すべて読み取りだけ):
   - 未コミットの変更・未追跡・無視されたファイル: `git -C <パス> status --porcelain --ignored`
     - 無視されたファイル(`!!` の行)は、一覧と大きさ(`du -sh`)を表に載せる
   - 未 push のコミット: 追跡先があれば `git -C <パス> log @{upstream}..HEAD --oneline`。無ければ「追跡先なし」と書く
   - 既定ブランチへの取り込み: `git merge-base --is-ancestor <HEAD> <既定ブランチ>` の終了値。squash merge は取り込み済みに見えないので、PR の状態も見る
   - PR の状態: `gh` があれば `gh pr list --head <ブランチ> --state all --json number,state,mergedAt,headRefOid,baseRefName`。無ければ「PR 状態は未確認」と書く
     - 同名ブランチの過去の PR も返るので、PR の `headRefOid` が worktree の今の HEAD と一致するか(または HEAD が既定ブランチに取り込まれているか)を確かめる
     - 対応が分からなければ「確認が必要」にする
   - detached HEAD: ブランチ名が無いので PR の状態は「未確認」。`git branch -a --contains <HEAD>` で、どのブランチにも含まれないコミットがあれば「確認が必要」(消すと辿れなくなる)
   - ロック: `locked` の理由を読む。理由にプロセス番号があれば、生きているかを調べる
     - 主な判定は `/proc/<番号>` の有無。`kill -0` を使うなら、権限エラー(EPERM)は「生きている」と読む
     - 番号の再利用で誤判定しうるので、迷ったら生きていると判定する
   - 最終使用日(参考値): `git -C <パス> rev-parse --git-dir` が指す管理ディレクトリの `logs/HEAD` と `index` の更新時刻と、直近のコミット日のうち最も遅いもの
     - コミットしない編集は反映されない。確かめられなければ「未確認」と書く
4. 中を作業ディレクトリにしているプロセスを調べる。
   - Linux は `/proc/*/cwd` の指す先が worktree の下か、`lsof +D <パス>`(あれば)で調べる
   - 調べられない環境では「プロセスは未確認」と書き、その worktree は「確認が必要」に入れる

## 2. 作業用コンテナと作業ファイルを集める

- コンテナ: コンテナの実行環境(`docker` など。以下 `<実行環境>`)があるときだけ調べる。無ければこの節を省き、省いたことを報告に書く。
  - ラベル付き: `<実行環境> ps -a --filter label=dev-workflow.task`
  - 停止中: `<実行環境> ps -a --filter status=exited`。ラベルが無いものは、この skill と無関係な利用者のものを含みうる。持ち主が分からないと明記する
  - 中だけにある変更: `<実行環境> diff <ID>` などで確かめる。変更があるもの、確かめられないものは、失われる内容を示す
  - 名前付きボリュームを持つものは、ボリュームの名前と大きさ(`<実行環境> system df -v` など)を書く
- 作業ファイル: 作業の残りの候補を、削除せず一覧にする。
  - リポジトリ直下とホーム直下の `pr-body-*.md` の類
  - `.claude/reviews/` の古いログ。候補は、完了と確かめられたタスクのログだけ(`完了_` のファイル、または作業記録の置き場で完了と分かるもの)
    - タスクのファイルが無いことだけでは候補にしない(Issue で作業を管理するプロジェクトでは、進行中でもファイルが無い)
    - 作業記録の置き場は、権威参照ファイルや profile で調べる
    - 状態が分からないもの、`進行中_`・`保留_` のログは「残す」(do-task の反復の番号づけと、新規着手の判定に使うため)
  - 中身が PR 本文などと同じか、ほかに残っている版があるかを確かめて書く
- 記録だけ残った worktree(`prunable`)は、`git worktree prune --dry-run -v` の出力を全件、表に載せる。
  - `prune` は 1 件ずつ選べない。場所を移しただけの worktree や、一時的に見えない worktree の登録も消える。
  - 場所を移しただけと思われるものは、`git worktree repair <新しいパス>` を先に案内する。

## 3. 分類する

| 対象 | 削除してよい | 確認が必要 | 残す |
|---|---|---|---|
| worktree | 変更・未追跡・無視されたファイル・未 push が無い。既定ブランチへ取り込み済みか、PR がマージ済みで HEAD と一致する。使用中でなく、ロックが無い | 無視されたファイル・未 push がある(未コミットの変更・未追跡があるものは下の「消せない」)。PR が未マージか閉じただけ。PR や既定ブランチやプロセスが未確認。追跡先なし。detached で孤立したコミットがある。ロック付きで持ち主が死んでいるか分からない | プロセスが作業ディレクトリにしている。ロックの持ち主が生きている。ロックの理由が `dev-workflow-loop:` で始まる |
| コンテナ | ラベル付き・停止中・ボリュームが無く、中の変更が無いと確かめた | ボリュームがある。ラベルが無い。中の変更がある、または確かめられない | 動作中 |
| 作業ファイル | なし | 常にここ。ほかに残っている版を確かめた上で 1 件ずつ | `進行中_`・`保留_` のタスクのログ |

- 迷ったら「確認が必要」にする。
- **消せない(案内だけ)**: 未コミットの変更か未追跡がある worktree。`--force` なしの `remove` が拒否するので、分類は「確認が必要」でなく「消せない」とし、4 節 4 の質問の対象から外す。
- 理由が `dev-workflow-loop:` で始まるロックは、無人ループの除外の印。この skill では消さない。
  - ループが止まっているときに、人が [../ship-task/references/loop.md](../ship-task/references/loop.md) の手順(`git worktree unlock` → `git worktree remove`)で片付けるよう案内する。
  - 外部レビューの一時ツリー(外部のレビュアーに見せるために作る、ファイル一式の一時的なコピー)は、元のリポジトリから切り離されているので、worktree の一覧には通常出ない。出たときは触らず報告する。
- 未コミットの変更と無視されたファイルは、ファイル数・増減の行数・大きさを添える。ほかにコピーが無いので、消すと失われると書く。
- 結果は表で出す(1 行に 1 つ。列は 種類・パス・分類・理由・大きさ・最終使用日)。

## 4. 承認を得て消す

1. `--dry-run` のときは、ここまでの表を出して終える。
2. 「消せない」の worktree(未コミットの変更か未追跡がある)は、`--force` なしの `git worktree remove` が拒否するので、この skill では消せない。
   - 削除の承認は求めない。中身を退避するか手で消すよう案内する。
3. 「削除してよい」を、一括で質問で確認する。選択肢は「すべて消す / 個別に選ぶ / 消さない」。
4. 「確認が必要」は 1 件ずつ質問で確認する(「消せない」は除く)。ほかにコピーの無いもの(無視されたファイル・ボリューム)は、失われる内容を示してから聞く。
5. 識別情報は、表を作る時点(1・2 節で読んだ値)で控える。
   - worktree: HEAD と `status --porcelain --ignored` の結果
   - 無視されたファイル: 1 件ずつ(ディレクトリは中を辿って)パス・大きさ・sha256(または更新時刻)
   - コンテナ: ID・状態と、`<実行環境> diff <ID>` の変更一覧
   - ボリューム: 名前・作成日時・大きさ(`<実行環境> volume inspect` と `system df -v` など)
   - 作業ファイル: 大きさと更新時刻(または sha256)
6. 消す直前に、控えた値を取り直して照らす(表を見せてから承認までの変化も検出する)。
   - 無視されたファイルは、追加・削除・内容の変化を照らす。
   - コンテナの変更一覧とボリュームの値も取り直して照らす。
   - 変わっていたら消さず、再提示する。
   - 取り直せない対象、確かめられない対象は消さない。
   - 中を作業ディレクトリにしているプロセスの再確認も行う。あれば、先に報告して消さない。
7. 消す。
   - worktree は `git worktree remove <パス>`(`--force` なし。`-f` も `-f -f` も使わない)。失敗したら理由を報告して次へ進む。
   - ロック付きは、個別に承認を得て、持ち主が死んでいると再確認したときだけ、`git worktree unlock <パス>` の後に `remove`。
   - コンテナは `<実行環境> rm <ID>`(`-f` なし)。ボリュームは個別に承認されたものだけ `<実行環境> volume rm <名前>`。
   - 作業ファイルは、承認された 1 件ずつ。
8. 記録だけ残った worktree は、`git worktree prune --dry-run -v` の全件を示して、まとめて 1 回だけ承認を得る。
   - 消す直前に dry-run を取り直す。件数と中身が承認時と同じで、未承認の対象が無いときだけ `git worktree prune` を実行する。

## 最終ゲート

削除したもの・残したものとその理由の一覧が成果物なので、[../do-task/references/writing-for-people.md](../do-task/references/writing-for-people.md) の「8. 完了報告の型」は使わない。
- `--dry-run` は分類の表を、削除後は実際の結果の一覧を報告する。消せなかったもの・未確認のものを省かない。

- [ ] 集める段階で、読み取り以外の操作をしていない
- [ ] 消したものは、すべて承認を得たものだけ。一覧と、消せなかった理由を報告した
- [ ] `--force` も `-f` も使っていない
- [ ] 消す直前に識別情報を取り直して照らした
- [ ] ローカルのブランチとリモートのブランチを消していない
- [ ] 使用中の worktree を消していない。プロセスがあったものは、先に報告した
- [ ] 無視されたファイルがある worktree を、個別の確認なしに消していない
- [ ] コンテナの実行環境が無いとき、省いたことを報告に書いた
- [ ] 報告が [../do-task/references/writing-for-people.md](../do-task/references/writing-for-people.md) の決まりに沿う
